# KomgaScraper

Komga 漫画服务器元数据刮削器（Windows 桌面版），基于 Bangumi API。
逻辑移植自油猴脚本 [dyphire/KomgaBangumi](https://github.com/dyphire/KomgaBangumi)，
并包含 [dyphire/KomgaMylar](https://github.com/dyphire/KomgaMylar) 的 Mylar 导出与文件夹打标签功能。

技术栈：C# / .NET 8 + WinForms（无第三方 NuGet 依赖）。

## 功能

- **连接管理**：Komga 地址 + API Key（或账密），测试连接，库下拉选择，设置**便携持久化**到程序目录 `data\settings.json`
- **系列浏览**：加载所选库全部系列（分页拉取直至服务器总数，缺失时日志警告），关键字过滤 + **刮削状态筛选**（全部/未刮削（无链接）/已刮削（有链接）/**未刮封面**/**未刮简介**/**待补全（封面或简介缺）**/**已完整（封面+简介都有）**），点击列头排序，**全选/全不选**按钮。
  列表有**封面**和**简介**两列：✓=已刮、✗=没刮、…=正在后台确认。
  这两列看的是**真实内容**（封面=服务器上是否已有用户上传的系列封面；简介=简介字段是否非空），**不只是看有没有链接**；
  状态记在 `data\scrape-state.json`，加载系列时后台自动补查没记录过的系列（并发 3，不打扰服务器）
- **刮削元数据**：对勾选系列按标题搜索 Bangumi → 弹出候选面板（封面+标题+作者）→ 选中后更新
  Komga 系列元数据（标题/排序/简介/出版社/状态/分级/总数/genres/tags/作者/别名/链接）
- **全自动模式**（勾选"全自动"后刮削/批量不再逐个弹候选框）：Bangumi 标题/原名/别名精确匹配 →
  **AI 识别作品**（拿不准时直接问 AI 这部作品叫什么，一次拿到日/中/英三个名字，再用三个名字分别到
  Bangumi / BookWalker / Mox 重搜）→ **BookWalker 本地索引回退** → **AI 智能选择**（多候选模糊时）→
  **Mox 中文源回退** → **AI 中文标题译日文再查 BookWalker** → **MangaDex 回退**（免密钥公开 API，
  英文区收录而 bgm/目录站没有的作品；标题取 zh-Hans、简介走 AI 翻译）→
  **百度百科兜底**（所有源都没有的冷门漫画），失败加入"手动匹配"收藏夹。
  单条回退失败不再中断整条链（例如 BookWalker 刮削失败仍会继续试 Mox）。
  AI 识别的结果按进程内缓存，同一系列不重复问
- **搜索词解析兼容中文压制组命名**：`[作者][标题][出版社][汉化组][状态]` 这种和日文惯例相反的命名，
  会把「像标题的方括号段」按 拉丁字母占比 排到前面（作者/汉化组多是罗马字），
  **含假名的段再靠后半档**（假名段多半是日文作者/原名——[アタモ卜][食物战线无异状] 的第一搜索词是标题不是作者），
  多标题用 `、` `/` `_` 再拆（`[作者][苍蓝钢铁战舰、苍蓝钢铁的琶音]` 两个都能搜），
  并跳过 `未完/汉化/扫描/水印/嵌字/修图/扫图/熟肉/Vol.01-Vol.18/1-100完/38全` 这类元信息段
  （`zero有水印` 曾被当搜索词撞名《ZERO》刮错，现在整段剔除），
  以及**出版社段**（东立/角川/青文/长鸿/大然/尖端/玉皇朝/文化传信/电子版/bili/汉化组……这些垃圾词
  曾被当成搜索词拿去搜导致大量"搜不到"，现在直接过滤）；剥完 [] 剩下的残渣（如 `38全`）也不当搜索词；
  嵌套方括号（如 `[Fate/stay night [Unlimited Blade Works]]`）也能正确拆出外层和内层标题，不再产生 `]` 残片；
  最多依次尝试 4 个候选词，命中即止
- **精确匹配宁缺毋滥（宁可跳过也不刮错）**：候选命中标准 = 规范名相等，或包含关系且**多出来的残留
  不含拉丁字母/水印/汉化等垃圾词**（`乱马1/2 完全版 ⊃ 乱马1/2` ✓ 版本词放行；
  `zero有水印 ⊃ ZERO` ✗ 拒绝——残留是水印垃圾，曾把《食物战线无异状》刮成《ZERO》）。
  全链路（Bangumi/BookWalker/Mox/MangaDex/百度百科）共用这套标准；所有源都无精确命中 → **直接跳过**
  （加入"手动匹配"收藏夹），绝不拿模糊相似的结果凑数
- **AI 匹配**（可选）：OpenAI 兼容接口（默认 DeepSeek），两用：
  **识别作品**——搜索词打不中时问 AI 这是什么作品（日/中/英名一次拿全，然后按原名重搜三源）；
  **智能选择**——无精确匹配但候选多个时由 AI 挑最合适的。
  候选太多时先按相似度排序截取前 12 个再给 AI，避免把 AI 撑爆
- **AI 简介翻译**（可选）：勾选后，刮削时**非中文简介自动翻译成简体中文**再写入（BookWalker 源基本都是日/英文简介）；
  已是中文的简介自动跳过、不发请求；翻译失败保留原文，绝不影响刮削本身。系列简介与每卷简介都会处理
- **AI 补写简介**（可选）：Bangumi/BookWalker/Mox **三源都没有简介**时，让 AI 根据作品名/作者
  补写一段 80–160 字的中文简介（只当元数据用，AI 也不认识的作品保持空，宁缺毋滥）；Dry-run 下只记录不写入
- **BookWalker 数据源**（可选）：从官方 `data.bookwalker.com` 拉取目录库（55MB zst → 解压 sqlite → 本地索引），
  之后 Bangumi 无结果时用 BookWalker 英/日文目录兜底，Bangumi 搜索无结果时也会给出 BW 候选卡片。
  该地址在 Cloudflare 后面，程序直连可能返回 **403**——此时用设置里的
  **打开下载页**（浏览器下载）→ **导入本地文件…**（选 `bkwk-db.sqlite.zst`，也支持已解压的 `.sqlite`）即可，见下节
- **BookWalker 目录库榨取**（v2 索引，把 9.4 万行 products / 785 个标签都用上）：
  - **系列级**：标题 / 简介（自动去 HTML 标签）/ 出版社 / **出版品牌**（label，如 VIZ Media）/ 作者 /
    **类型 → Komga genres**（`tags.namespace=1`：Romance、Action、Shounen…）/ **题材 → Komga tags**
    （`namespace=2`：Prince、Military…）/ 别名 → alternateTitles / **首发日** / **总卷数**（只数顶层卷，
    不再把「分话」算进去）/ **状态**（`complete` 标签才是完结，否则连载中）/ **阅读方向**（`series.type=1`
    漫画 → 从右往左）/ `Bw` 链接。可用设置里的「写入类型/题材标签、阅读方向」开关关闭
  - **每卷级**：**发售日**（`products.on_sale_at`，94,166/94,166 全有）/ **ISBN-13**
    （`product_external_ids.type=3`，13 位数字）/ **单卷简介**（与系列简介不同的那 10,682 卷）/
    **单卷封面**（与系列封面不同的那 49,630 卷）；卷号用 `products.display_order`，只取顶层卷
    （`parent_content_id IS NULL`，排除「分话」）
  - **跨源补空**：Bangumi 命中时也会用 BookWalker 补空缺的 **ISBN / 发售日 / 单卷封面**（语言无关字段），
    不覆盖 Bangumi 的中文简介。**匹配词带 Bangumi 的日文原名与别名**——本地是中文名时，
    直接拿中文标题查 BW 目录（只有日/英文标题）永远查不到，现在会连同 Bangumi 原名/别名一起试；
    批量回退链的最后一环还会让 AI 把中文标题翻成日文原名再查一次
  - **防串卷保护**：两边的册数差距超过 25%（至少 2 册）就跳过每卷对齐并记日志——
    目录库里很多条目是「按话连载」（比如 291 条），硬按卷号对齐会把第 12 话的 ISBN 写到第 12 卷上
- **刮削元数据+封面**：额外上传系列封面与每卷书封面（单行本关联匹配，多尺寸候选，**不做大小过滤**——
  2KB 也是封面；仅服务器 413 时自动换下一档，相同大小的封面不重复上传）
- **纠正匹配**：**「纠正匹配」按钮 / 列表右键 →「纠正匹配」**——逐个弹**候选面板**重新选正确条目
  （四源候选按来源分组展示：Bangumi/BookWalker/Mox/MangaDex/百度百科，空源不显示；面板右侧有**详情区**：
  大封面 + 中文名/原名/作者/别名/来源 + **完整简介**，选之前就能确认是不是这部），面板里还有
  **「手动输入 Bangumi 链接/ID…」**——直接粘贴 `https://bgm.tv/subject/xxxx` 或输入数字 ID（手动输入是纠正的子集；
  搜索不到候选时面板照样弹出，手动指定条目的路子永远在）。选中的新条目会**覆盖旧的错误匹配**
  （旧 Btv/Bw/Mox/MangaDex/百科链接剔除、被锁住的字段解锁重写、全部卷强制重抓），新列表状态自动刷新。
  搜索词优先取**文件夹名**（元数据标题已被旧匹配污染时不再作搜索词）
- **覆盖匹配**：**「覆盖匹配」按钮 / 列表右键 →「覆盖匹配」**——对勾选系列**重走一遍自动匹配全链路**
  （与批量精确匹配同一套源回退：Bangumi 精确 → BookWalker → AI 原名重搜 → Mox → MangaDex → 百度百科），
  但**完全不看旧的链接和元数据**：不跳过已有 Btv 链接、搜索词只用**文件夹名**（元数据标题可能已被旧匹配污染），
  命中即以 ReplaceMatch **覆盖旧的错误匹配**（旧链接剔除、被锁字段解锁重写、全部卷强制重抓）。
  **全程无弹窗、不再手动选候选**；没匹配到的系列保持原样（旧数据不动，也不进"手动匹配"收藏夹），
  覆盖成功的系列会自动从"手动匹配"收藏夹移除——批量清理程序匹配出来的坏数据就用它
- **导出日志**：日志除界面显示外**自动写入** `data\logs\log-日期.log`；**④ 工具 → 导出日志**
  不弹任何对话框——直接把最近 3 天日志合并成带时间戳的 txt 存到**下载目录**（下载目录不可写时自动退回
  桌面 / 程序 data 目录），存完自动打开资源管理器并选中该文件
- **Mox 中文第三源**（bookof.moe）：Bangumi 和 BookWalker 都没命中时，自动按**中文名**到
  Mox（繁体中文漫画库）搜索兜底；命中后写入中文标题/简介/作者/状态（连载/完结/停更/弃坑→Komga 状态）/
  出版社（版本）/题材（分类）/R18 分级 / `Bof`+`Mox` 链接，**搜索结果行里直接带封面 URL**（候选卡片直接显示封面），
  并从封面帧页拉**每卷封面**（第 1 张同时作系列封面）。
  **串行访问**：bookof.moe 在 Cloudflare 后面，并发/猛刷会触发 520——程序对它**严格串行**（搜索、详情、封面全部排队，
  请求间隔 500ms），偶发 520/5xx 自动退避重试（1.5s/3s 两轮），彻底告别"明明站点没问题却报错"。
  只补 Komga 缺失的字段，不覆盖已有中文数据；走与封面下载相同的代理
- **百度百科兜底源**（baike.baidu.com）：Bangumi/BookWalker/Mox/AI 全都没命中时，按**中文名**到
  百度百科查词条（搜索框的开放卡片接口，无需密钥，**国内直连不走代理**）。很多 bgm 收不收的冷门漫画
  （如《食物战线无异状》《名侦探贵鸟同学》）百科都有。命中后写入：**中文标题/排序标题/简介（词条摘要本身是中文）/
  出版社（出版社/其他出版社卡）/作者与作画/原版名称→别名/类型→genres/阅读方向（日漫→RTL）/`Baike` 链接**，
  元数据+封面模式还会把**词条概述图**传作系列封面（唯一可用的图）。词条命中标准与其它源一致
  （规范名相等/包含），不会张冠李戴。设置 → 刮削行为 → **「百科兜底」** 可关（默认开）
- **批量精确匹配**：对勾选系列（不勾选则整库）自动精确匹配，已有 Btv 链接的跳过（可设置强制刷新），失败系列自动加入 Komga "手动匹配" 收藏夹，带统计（批量层并行可调，见"批量并发"）
- **导出 Mylar series.json**：导出库内系列元数据为 Mylar 格式（`version 1.0.2`），保持库内相对目录结构，可选下载封面（oneshot 系列导出为 `xxx.oneshot.json`）
- **程序打标（必打，可追溯）**：**只要用了程序的任意一个功能对库里进行了操作，就会带上 MACHINE 标签**——
  不是可选项：刮削三条源路径（Bangumi/BookWalker/Mox）写字段时打；封面、卷数据等写入即使没写标签字段，
  也会自动补一条只带标签的 PATCH 确保 MACHINE 落上；一键打标同样必打（连 tags 被锁定的系列也照样打，
  版本标记词才会尊重锁）。在 Komga 里按标签一筛，就能看出哪些系列是程序整理刮削过的。
  已带 MACHINE 的不会重复写（幂等）
- **版本标记（多版本不刮平，[] 命名格式）**：刮削会把标题替换成刮到的名字，你文件夹里区分版本的标注
  （爱藏版/完全版/新装版/典藏版/文库版/无修版/电子版/境外版/b漫版…）会被抹平 → 多版本系列全清一色。
  现在刮削时会从**文件夹名**提取这些标记（对齐 KomgaMylar 的 tag_by_foldername）：
  版本词 + 出版社段后面的**汉化组/来源段**（ZD×Nearfly、C.C、堕落的猴子…）+ 尾部**（BW原档/提取档）括号** +
  **出版社词本身** → **标签 + 标题后缀**，**一个后缀一个标签**（乱马五份拷贝：大然+join / bili / 境外版+bili / 文传+C.C / 无标注，一眼可分辨）。
  标题后缀用**方括号**格式（乱马1/2 [境外版][b漫版]，连续标记紧贴成一组，比全角括号美观）；
  旧版写过的全角括号后缀（乱马1/2（join））会在下次刮削/打标时**原位归一成 []**，不重复追加；
  TitleSort 仍是无后缀净标题，排序不受影响
- **版本标记黑白名单**（设置 → 版本标记）：内置词表认不出的后缀也能按你的口径落标签——
  **白名单**里的词命中文件夹后缀就落一个标签（例如填 `C.C`，[乱马1/2][文传][C.C]38全 就有 C.C 标签）；
  **黑名单**里的词命中的标记直接丢掉——不落标签、标题里残留的旧后缀也会被清掉
  （例如填 `join`，乱马1/2（join）→ 乱马1/2，join 标签剔除；已有标签里的黑名单词一并清）。
  每行一个词，逗号分隔也行；空名单 = 只用内置词表，行为不变
- **版本标记打标（一键修复旧库）**：**④ 工具 → 打标**——不动简介/链接，对当前库逐系列补：
  文件夹标记 → 标签+标题后缀、出版社关键词标签、publisher 为空时填充、追加 MACHINE 标签；
  已经被刮平的旧标题可以一键恢复标注（Dry-run 先预览）
- **Dry-run 预览模式**（默认开启）：只记录将要执行的 PATCH/上传，不实际修改，确认无误后取消勾选再执行。
  **批量精确匹配、刮削、文件夹打标签都遵循这个开关**，预览时日志会逐条列出将要发送的 PATCH
  （含 series 的字段摘要与每个 book 的 title/简介/发售日/ISBN/作者），不会偷偷写库
- **改动留痕并入日志框（首页更清爽）**：不再单独占一个"改动预览"框——**Dry-run 执行时日志框逐条实时列出"将…"**，
  真实模式则留痕"已…"（`[改动]` 行），刮削/批量/纠正匹配/打标/编辑器保存，所有写库动作都汇到日志框
  （状态栏显示"改动 N 条"；文件日志同步留痕，导出日志就能拿到全文）。
  首页只有**信息框（列表）+ 日志框**两块，**鼠标放到中间缝隙可拖动调整两框占比**
- **搜索栏 + 编辑单部**：侧边栏 ② 有**全库搜索框**（跨库按标题/原名检索，不用先选库再加载），
  命中后**双击行**或点**「编辑单部」**打开编辑器（三个页签：系列信息 / 标签·别名 / 每卷）：
  系列封面（选图更换）/标题/排序标题/状态/阅读方向/出版社/语言/发售日/总卷数/分级/简介，
  标签/题材/作者/别名/来源链接（标签页），以及**每卷**——逐卷改标题/卷号/发售日/ISBN/简介、
  **选图换卷封面**（带缩略图列表）。保存=只提交改动字段，自动补 MACHINE 标签，锁字段原样回传不会翻转；
  "每卷"里还有**「重刮每卷（按卷号对齐）」**按钮（遵循主界面 Dry-run 开关）
- **卷封面按卷号对齐（乱马1/2 每卷封面错位修复）**：Bangumi 很多系列的单行本关联条目 name_cn 是
  **空字符串**（不是 null），旧逻辑退化成"按 Bangumi 列表序号"当卷号，而关联列表按 subject ID 排序、
  与卷序毫无关系 → 乱马 38 卷的封面/ISBN/简介整体张冠李戴（Vol.02 拿到第 27 卷的封面，四份拷贝全乱）。
  现在先挑非空名字段再解析卷号（`乱马1/2 (01)`/`Vol_35`/`第12卷`/`v01`/全角括号都能解析），
  两个名字都解析不出才按列表序兜底并告警。**修库方法**：在"编辑单部 → 每卷"点
  **「重刮每卷」**，或对勾选系列再跑一次"刮削元数据+封面"/"覆盖匹配"——
  会按卷号重新对齐每卷封面、简介、发售日、ISBN（封面大小不同即自动换图）
- **挂后台（托盘）**：点 X 或最小化 = 缩到系统托盘继续干活，不再弹"请先取消"；任务跑在托盘里照样执行，
  悬浮提示显示进度，结束时弹气泡。回窗口：单击/双击托盘图标或右键 → 显示主窗口；**真正退出走托盘右键 → 退出程序**
  （任务运行中退出会先自动取消并等收尾）

## 快速开始

1. **先把压缩包解压到任意文件夹**（不要直接在压缩包里双击运行，否则设置无法保存），然后启动 `KomgaScraper.exe`
2. 填入 Komga 地址（如 `http://localhost:25600`）和 **API Key**（Komga WebUI → 设置 → API 密钥），点 **测试连接**
3. 选择库 → **加载系列**
4. 勾选要刮削的系列 → **刮削元数据**（Dry-run 先行预览）→ 关闭 Dry-run 真正执行

> **运行位置提示**：请把程序解压放在**普通目录**（如 `D:\KomgaScraper\`）。放在某些被特殊工具
> （如 AI 沙箱工作区）保护过的目录里运行时，Windows 可能对这些目录带"拒绝删除子项"类限制，
> 程序的日志写入等操作会因此变慢或报"拒绝访问"——与程序本身权限无关，换个普通目录即可。
> **④ 工具 → 打开数据目录** 已改为直接启动 explorer 打开，受限目录下也能正常弹出窗口。

## 绿色便携（重要）

程序不在系统目录里留任何东西，所有数据都在 exe 同目录的 `data\` 文件夹中：

```
KomgaScraper\
  KomgaScraper.exe
  e_sqlite3.dll
  data\
    settings.json       ← 全部设置（地址 / API Key / 代理 / AI 配置）
    scrape-state.json   ← 每个系列的封面/简介刮削状态（列表 ✓✗… 列与筛选的数据源）
    bkwk-db.sqlite      ← 点"下载并建索引"后才有
    bkwk-index.json.gz  ← 同上
    logs\
      log-20261009.log  ← 自动日志（崩溃也能拿到全文；「导出日志」直接在下载目录生成 txt）
```

- 复制/移动整个文件夹即可迁移，不会写 `%APPDATA%`、`%TEMP%` 或注册表，也不需要任何额外目录权限；
- 主界面 **④ 工具 → 打开数据目录** 可直接打开该文件夹；
- 若设置无法写入（例如放在只读目录、或直接在压缩包内运行），程序会在日志和弹窗里明确报错，不再静默失败。

## BookWalker 数据源怎么拿到（403 必看）

`https://data.bookwalker.com/bkwk-db.sqlite.zst` 挂在 Cloudflare 后面，**非浏览器客户端常被挡（HTTP 403）**，
这不是程序 bug。设置 → BookWalker 数据源 提供三条路：

| 按钮 | 说明 |
|---|---|
| **直接下载建索引** | 程序直连下载 + 解压 + 建索引（约 55MB）。网络能过 Cloudflare 时最省事；走 Bangumi 代理设置 |
| **打开下载页** | 用系统浏览器打开上面的地址（浏览器能过人机校验），下载 `bkwk-db.sqlite.zst` |
| **导入本地文件…** | 选择刚下载的 `bkwk-db.sqlite.zst`（**也支持**自己解压出的 `.sqlite`/`.db`，按文件头自动识别），本地解压并建索引 |

推荐流程：**打开下载页 → 浏览器下载 → 导入本地文件… → 保存**。
导入在本地完成，不联网；索引生成后主界面日志会显示
`BookWalker 索引已加载（14,265 个系列，55,680 卷，格式 v2）`（约 7MB，构建约 4 秒）。

> 索引格式升级到 **v2**（多了每卷数据与类型/题材标签）。旧的 v1 索引仍能加载，但主界面会提示
> 「索引是旧格式」，重新导入/重建一次即可拿到全部字段。

> 已知网络问题：`c.bookwalker.jp`、`bookwalker.jp`、`d2snwnmzyr8jue.cloudfront.net`、
> `lain.bgm.tv` 在部分网络下会被 DNS 污染或直接超时而无法下载封面。
> **配好下面的代理即可解决**（封面下载与 Bangumi API 共用同一代理）；
> 未配代理时 BookWalker 的**封面**会失败并记日志，但**纯数据库字段（简介/发售日/ISBN/标签/别名）
> 不受影响**——这些才是目录库的主要价值。

## 网络说明（重要）

`api.bgm.tv`（API）和 `lain.bgm.tv`（封面图）在部分网络下无法直连（表现为**连接超时**，或
`由于连接方在一段时间后没有正确答复…lain.bgm.tv:443`）。请在 **⚙ 设置 → 代理** 里配置：

| 项 | 说明 |
|---|---|
| 协议 | 不使用 / **HTTP** / HTTPS / **SOCKS4** / SOCKS4a / **SOCKS5**（Clash 的混合端口用 HTTP，纯 SOCKS 用 SOCKS5） |
| 地址 / 端口 | 例如 `127.0.0.1` + `7890`；只填主机名时按协议取默认端口（HTTP 7890 / SOCKS 1080 / HTTPS 443） |
| 账号 / 密码 | 代理需要认证时填（HTTP Basic 与 SOCKS5 用户名口令都支持） |

> **MTProxy 不支持**：它是 Telegram 专用协议，不能代理普通网页/图片请求。若你只有 MTProxy，
> 需要在本机用 SOCKS5 中转（如 `mtg` + 一个 SOCKS 桥），再在这里填 SOCKS5。

这个代理同时用于**三处**：Bangumi API、**外部封面下载**（Bangumi 与 BookWalker 的 CDN）、
BookWalker 目录库下载。**不影响与 Komga 的通信**（Komga 请求永远直连，不走代理）。

改完可点设置窗口里的「直接下载建索引」验证代理是否通；命令行等价验证：

```
KomgaScraper.TestCli.exe proxytest socks5://127.0.0.1:1080 账号 密码
```

NSFW 条目搜索需要在设置中填入 **Bangumi Access Token**（bgm.tv → 设置 → API，客户端生成）。

## 设置项

| 设置 | 说明 |
|---|---|
| Komga 地址 / API Key / 账密 | 服务器认证（API Key 优先） |
| Bangumi Access Token | NSFW 搜索 |
| 代理（协议/地址/端口/账号/密码） | Bangumi API + 封面下载 + BookWalker 下载共用；支持 HTTP/HTTPS/SOCKS4/SOCKS4a/SOCKS5 |
| Bangumi 匹配类型 | 漫画 / 小说（platform 过滤） |
| BookWalker 数据源 | 填下载地址（默认官方）；「直接下载建索引」或「打开下载页 + 导入本地文件」；索引存在时自动作为回退源 |
| 写入类型/题材标签、阅读方向 | 把 BookWalker 的类型（genres）/题材（tags）/出版品牌/漫画-小说标记/阅读方向写入 Komga（默认开） |
| AI 匹配 | 启用后填 OpenAI 兼容接口地址/Key/模型（默认 DeepSeek）；多候选模糊时智能选择 |
| AI 简介翻译 | 勾选后非中文简介（日文/英文）自动翻译成简体中文再写入；与匹配共用上面的 API Key，只做翻译不编内容 |
| 抓取单行本详情 | 每卷 简介/发售日/ISBN。Bangumi 走「单行本」关联条目，BookWalker 走目录库每卷数据（默认关） |
| 百科兜底 | 百度百科作为最终兜底源（其它源都查不到时按中文名查词条，国内直连不走代理；默认开） |
| MangaDex | 英文圈图源（免密钥公开 API，走代理）：百科兜底之前查英文区收录，标题取 zh-Hans、简介走 AI 翻译 |
| 批量并发 | 批量刮削时同时处理几个系列（默认 3，1=逐个；Bangumi 请求自动按节流间隔排队，不会因并发超速） |
| 批量强制刷新 | 已有 Btv 链接的系列是否重刮 |
| 版本标记黑白名单 | 白名单 = 后缀命中即落标签（内置词表认不出的也按你的口径落）；黑名单 = 命中的后缀丢弃（标签+标题旧后缀一起清）；每行一个词，空名单只用内置词表 |
| Dry-run 预览 | 主界面勾选框，默认开 |

## 速度说明

- **批量并行**：默认同时刮 3 个系列；系列内的每卷 PATCH/封面上传也并行（4 路），系列封面与书籍更新同时进行。
- **Bangumi 礼貌节流**：所有 Bangumi API 请求共享一个节拍（≥300ms 间隔，约 3.3 次/秒），并发再多也不会超速；这是公益接口，请勿调小。
- **跳过已刮削系列零请求**：优先用列表接口自带的元数据判断 Btv 链接，不再逐个 GET `/metadata`（部分 Komga 服务器对该端点返回 405，曾导致"已刮削的系列检测不到链接→每次全量重刮"）。实测 1072 系列的已刮削部分：全量重刮 ~19 分钟 → **0.3 秒**。
- **请求去重**：批量入口已取过的系列/元数据直接传给刮削流程，不再重复请求。

- `src/KomgaScraper.App` — WinForms 薄壳
- `tools/mock-komga.js` / `tools/mock-bangumi.js` — 本地 mock 服务器，用于离线端到端测试
- `tools/TestCli` — 测试驱动：
  - `dotnet run --project tools/TestCli` — 连 mock 的完整流程（设 `REAL_BANGUMI=1` 连官方 API）
  - `... -- bwimport` — BookWalker 导入建索引（sqlite / zst / 非法文件）
  - `... -- bwscrape` — **端到端**：用真实目录库建 v2 索引 → mock Komga，逐条校验 PATCH 内容 + 并行批量/请求去重/节流回归（36 项）
  - `... -- bwschema` / `-- bwprobe` — 只读诊断官方目录库的表结构与字段分布
  - `... -- aitest` — AI 匹配 + **AI 识别作品(jp/cn/en)** + **AI 补写简介** + 简介翻译 + 标题译日文（本地 mock 接口，含失败兜底与缓存命中断言）
  - `... -- matchtest` — **AI 识别驱动的匹配回退链端到端**：中文名搜不到 → AI 报原名 → 原名重搜 → AI 选候选 → 写库（全 mock；含 **MACHINE 标签 + 版本标记后缀断言**）
  - `... -- marktest` — **版本标记 + MACHINE 打标**：文件夹名标注检测（版本词/汉化组段/尾部括号）、标题后缀追加、FolderTagger 打标链端到端（全 mock，不联网）
  - `... -- moxtest` — Mox(bookof.moe) 第三源解析/刮削 + **520 自动重试** + **搜索行封面 URL** + 纠正匹配(ReplaceMatch) + 小封面不再拒收 + **封面/简介状态库持久化**（全 mock）
  - `... -- baiketest` — **百度百科兜底源**：真实接口两冷门漫画断言 + 未命中返回 null + JpegCoverUrl + **mock 兜底链端到端**（Bangumi 空 → 百科命中 → PATCH 字段断言）
  - `... -- titleparse [文件夹名...]` — 搜索词解析结果 + **垃圾词过滤断言**（出版社/汉化组/嵌套括号不进候选，不联网）
  - `... -- searchreal [代理] [名称...]` — 连真实 Bangumi 验证能否命中
  - `... -- proxytest [scheme://host:port] [账号] [密码]` — 解析各写法 + 真实下载一张封面（对比直连/代理）
  - `... -- realdry "标题片段"` — 用 `dist\data\settings.json` 连真实 Komga 做只读预演（**不写库**）
  - `... -- speedcheck [跳过数] [刮削数]` — 连真实 Komga 实测并行批量速度（**全程 Dry-run 不写库**）
